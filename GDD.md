# Perfect Zero — Game Design Document

*Current state as of this build. Engine: Godot 4.7 (GL Compatibility renderer). Made for GMTK Game Jam 2026, theme "Countdown."*

---

## 1. Concept

Perfect Zero is an arcade-reflex game about stopping countdown timers at exactly 0.00. Multiple timers run at once; the player clicks each one at the moment they judge it to be at (or nearest to) zero. Accuracy is graded continuously and converted into points and a score multiplier. Missing badly enough ends the run.

Two modes:
- **Arcade** — a fixed 12-stage campaign with hand-authored timer layouts, escalating in complexity and introducing new timer types one at a time.
- **Endless** — an infinite single 3×3 grid that continuously spawns timers, escalating in speed and density over time, with a lives system and three activatable powerups.

## 2. Visual and audio identity

- **1600×900 fixed canvas on desktop/web.** On Android, the canvas is portrait and **dynamically sized**: width is pinned at 900 (everything's dp/touch-target math is calibrated against it) but height is computed at runtime from the real device's aspect ratio (`Layout._compute_portrait_size()`), so the canvas's own aspect always exactly matches the physical screen's — this replaced an earlier fixed 900×1600 portrait canvas, which left real unfilled letterbox margins (painted over, not eliminated) on any device whose aspect wasn't exactly 9:16. `canvas_items` stretch mode either way (UI scales to fit any window/resolution).
- **Neon-on-black** aesthetic: near-black backgrounds (`#0a0a11`-ish), bright saturated accents per system (cyan, gold, red, purple, grey), glowing borders and outlined text.
- **Almost everything is still drawn at runtime, not imported.** Timer panels, buttons, particle-like bursts, toggle switches, sliders, and most icons are procedural — Godot `_draw()` calls and `GradientTexture2D`s, not image files. This avoids raster blur under the canvas's stretch scaling. The jam's AI-art-asset ban that originally drove this is no longer in force (jam submission is done; this is a proper release now), so this is a stylistic/technical preference going forward, not a hard constraint.
- **A small, deliberate set of hand-authored SVG icon files now exists** (`icons/title_*.svg` — title screen's Options/Help/Scores/Credits row; `icons/android_icon_*.svg` and root `icon.svg` — app/launcher icons; `icons/credits_heart.svg` — the Credits screen's thank-you heart; `icons/options_*.svg` — the Options screen's five row icons: speaker, note, eye, trash, and a deliberately flat/glow-less bug for the debug card). All hand-drawn vector paths, not generated images. Two rendering gotchas learned the hard way: Godot's runtime SVG rasterizer (thorvg) does not render `<text>` elements at all (renders blank) and does not correctly composite `<feGaussianBlur>`/`<feMerge>` glow filters (blurs the whole shape instead of adding a halo) — every icon in this project is built from plain paths/circles with no `<text>` and no filter, each one a translucent accent fill plus a bold accent-colored stroke boundary.
- **Zero external SFX.** All sound effects and the ambient drone bed are synthesized at runtime from sine-wave math into `AudioStreamWAV` buffers, played through a pool of `AudioStreamPlayer`s.
- **One external non-visual asset**: a licensed music track (`audio/menu_theme.mp3`, "Synthwave Retro 80s" by arpmedia, via Pixabay) used as menu music.
- Audio runs on two independent buses, **SFX** and **Music**, both under Master, so the two have separate volume controls. SFX carries a light low-pass/compressor/limiter chain to keep stacked synthesized tones from turning harsh.

## 3. Core loop: grading a stop

Every timer (except Golden and Decay, see below) counts down from a `start_time` toward 0.00. Clicking it stops it and grades the stop by **distance** — how far `current_time` is from zero at the moment of the click:

| Grade | Distance from 0.00 |
|---|---|
| PERFECT | ≤ 0.05 |
| GOOD | ≤ 0.30 |
| OKAY | ≤ 0.50 |
| MISS | ≤ 1.00 |
| FAIL | > 1.00, or the timer runs past zero unclicked |

Thresholds are inclusive on the upper bound (exactly 0.05 grades PERFECT, not GOOD). Distance is rounded to 2 decimal places before grading, matching what the digit display shows, so a value like 0.051 can't grade worse than what the player visually saw ("0.05").

A **FAIL** ends the run immediately in Arcade (the stage is lost) and costs a life in Endless.

## 4. Scoring

Two independent scoring models exist for the two modes, sharing the same base formula.

Every number in this section is **Inspector-editable** rather than hardcoded: the grade windows, the base-points constants, the per-grade multiplier deltas and the bonus factors are all `@export` vars on the `ScoreManager` autoload (a scene autoload, `scenes/ScoreManager.tscn`, for exactly this reason). They are the *single* definition, not a mirror of one — the grade windows in particular used to be constants on `TimerSlot`, and were moved rather than copied so the Inspector cannot retune what the Help screen displays while leaving the board grading by the old numbers. The values quoted below are the shipped defaults.

**Base points per stop:**
```
base_points(distance) = floor(200 × (1 − min(|distance|, 1))²)
```
Continuous and quadratic — a dead-on 0.00 is worth 200, falling off smoothly to 0 at distance 1.0. No cliff between grade tiers.

**Multiplier**, evolves per stop:
- PERFECT: +1.0
- GOOD: +0.5
- OKAY: unchanged
- MISS: halved (floored at 1.0)
- FAIL: reset to 1.0 (Arcade ends the run here anyway; Endless resets the segment)

**Arcade (Campaign) scoring — fully deferred:** nothing is shown to the player during play. Every stop is recorded silently (`grade`, `distance`, a per-stop `bonus_factor` — see below). At the end of the stage, the whole sequence replays in a scripted reveal (see §8) that visibly builds the tally and multiplier stop-by-stop, then multiplies them together for the final stage score. The multiplier is applied once, at the very end, not compounded per stop.

**Endless scoring — fully live:** each stop immediately adds to a running `stage_tally` and updates a live `multiplier`, both shown on the HUD as they happen. A FAIL banks `tally × multiplier` into the run's total, costs a life, and resets the segment to 0/1.0×. The run total is the sum of every banked segment. Endless multiplier is uncapped in both sub-modes currently (`multiplier_cap = -1`, i.e. no cap set at runtime — see EndlessRunner).

**Bonus factor** (multiplies base points, computed from the timer's type and stacked Red boosts):
- Golden: ×2.0 if the grade is PERFECT (it always is — see below)
- Blackout: ×2.5 on any scoring grade (PERFECT/GOOD/OKAY)
- Every Red-reaction boost a timer has received before it stops: ×(1 + 0.25 per stack), on any scoring grade
- All other types/grades: ×1.0

## 5. Timer types

Six types exist. All spawn at a fixed size, colored panel with a live digit readout.

| Type | Color | Behavior |
|---|---|---|
| **Normal** | pale lavender | Counts down plainly. No special rule. |
| **Red** | red | On stop, every *other* still-running timer on the board gets permanently sped up (+0.25× speed, additive, stacks with repeats) and its bonus-factor stack count +1 (worth +25% more points per stack when it eventually stops). |
| **Blue** | cyan | On stop, every other still-running timer is frozen (paused, no countdown) for 1 second. Multiple Blue stops stack the freeze duration additively. Frozen timers show a translucent blue overlay. |
| **Golden** | gold | Never counts down. Displays a fast-cycling random-digit blur instead of a real countdown, so the player can't "aim for 0.00" — any click is a guaranteed PERFECT worth 2× base points. Because it never expires on its own, a Golden left unclicked will stall a stage indefinitely in Arcade (by design — no forced auto-resolve). |
| **Blackout** | slate grey | Counts down normally but its digits go blank ("??.??") once inside its `blackout_duration` (default 1.5s) of zero — the player has to time it by ear/feel rather than by reading the number. Worth 2.5× base points on any scoring grade. Gets its own low "heartbeat" tick sound instead of the standard rising-pitch tick, for its whole life. |
| **Decay** | purple | The one type that counts *up* from 0.00, not down. Graded against its own four sequential windows (Perfect/Good/Okay/Miss durations, defaults 0.6/1.2/1.8/2.4s) rather than the global distance thresholds — whichever window the elapsed time currently falls in is the grade. Running out of all four windows resolves it as a MISS (never a FAIL — Decay can't cost a life/end a run by expiring). Border color steps through a purple gradient as it drains from bright to dim, most vivid at spawn to win attention immediately. Score uses the same base-points curve, driven by elapsed-time-normalized-to-total-lifetime as its "distance." |

Every stopped or expired timer holds fully visible for 0.4s, then fades out over another 0.4s before its slot is actually freed, so the outcome (color flash, grade sign, particle burst) has time to read.

## 6. Arcade (Campaign) mode

- **12 fixed stages**, each a hand-authored list of timers (type + start_time) laid out in centered rows (up to 3 per row).
- Stages 3 and 6 are **bonus stages**: all-Golden (5 and 9 timers respectively), so they cannot be failed — only completed.
- Progression is gated: `Level Select` shows every stage, but only up to the player's furthest-reached stage (+1) is clickable; the rest are visibly locked and greyed out.
- First time playing, pressing **ARCADE** goes to Level Select (not straight into Stage 1), so a new player sees the full 12-stage roster with only Stage 1 unlocked — communicating the game's scope up front.
- A stage ends the instant every timer on the board is stopped (clear) or the instant one is FAILed (loss). A stage clear/fail waits a short pause (0.7s) after the last stop before cutting to the result screen, so the final stop's flash/tick has time to land.
- **Per-stage best score** is tracked and persisted (`highscore_stage_N`). Retrying a stage keeps the campaign's running total anchored to the *best* of any attempt, not the latest.
- **First-seen-type tutorial popups**: the first time a stage introduces a timer type the player's save has never seen, a one-time modal demonstrates it before the stage's timers spawn — data-driven off stage contents, so reordering stages needs no extra wiring. The popup shows a live tile running the exact same scripted animation the Help screen's own legend uses (real countdown/blur/climb, real grade resolution, real per-type score bonus), auto-playing the instant it opens rather than a static name/description card; Red and Blue additionally spawn two bystander Normal timers reacting, since a single tile can't show an effect that lands on *other* timers. The demo **loops continuously** rather than playing once and freezing — GOT IT stays locked until the first full playthrough finishes, then unlocks and stays unlocked while the animation keeps replaying, so a player who was still reading the description isn't left looking at a dead final frame.
- **One-time first-ever intro demo**: before a brand-new player's very first stage, a ghost cursor glides onto a live practice timer (visually identical to a real one) as it counts down, then the countdown eases to a dead stop just short of 0.00 and waits — unclickable until then, so no premature click can grade as anything but the PERFECT it settles into. The player has to click it themselves to proceed. This replaces relying on read text to teach "stop it as close to 0.00 as you can": it's shown once ever, then never again.
- **No powerups in Arcade.** Powerups are Endless-exclusive.

### The stage-clear reveal sequence

Because Arcade scoring is deferred, the payoff is a full scripted "reveal" on the result screen, structured as:

1. **Holding-breath beat**: screen dims slightly (~0.38 alpha), audio ambient bed is already silent (stops automatically leaving PLAYING), holds for a short beat (~0.1s fade-in + hold) before anything moves — a deliberate silence right before the payoff. Alongside this beat, a single **quality signal** for the whole stage (the same aggregate the finale's tier is computed from — see step 3) sets a quiet background glow/tint for the rest of the reveal, so a strong clear reads differently from the very first frame rather than only once the finale lands. Deliberately subordinate to the finale's own colour wash — a soft persistent tint, not a flash — and scaled down (not removed) by "Reduce screen effects."
2. **Stop-by-stop tally**: each recorded stop counts up onto the tally display in sequence, each landing with: a grade sign popup (squash-and-stretch entrance) at a fixed on-screen anchor, a radial particle burst sized/colored by grade (reusing the game's normal click-burst effect), a one-shot audio stinger that climbs in pitch on same-grade streaks, a secondary particle "ring" thrown outward from the grade sign (skipped below OKAY grade to avoid visual mush on long stages), and — during the stretch of the reveal — a running "intensity" value that escalates with consecutive PERFECTs, brightening/growing every subsequent effect (burst size, ring size, stinger loudness) so a clean stage visibly and audibly builds momentum. **Skippable**, for replaying a stage to chase a better score: a tap jumps straight to the finale with the tally instantly settled at its true final values (no partial/interpolated numbers ever shown); holding compresses the pacing instead of jumping, so the per-stop effects still play, just faster. Works with mouse click or the keyboard confirm key.
3. **The finale**: after a beat, the multiplier "slams" into the tally to produce the final stage score — with the single biggest hit-stop and camera-punch in the entire game (deliberately bigger than anything in live play, since this is Arcade's only payoff moment), a dedicated six-voice "final slam" stinger reserved exclusively for this moment, and a full-screen colour wash whose color and particle-burst scale depend on a computed stage-quality tier (derived from the average grade quality across all recorded stops — not from the optional/often-unset `target_score` field). Tiers are grey → cyan → gold, matching the screen's own colour language (see below) — no green anywhere on this screen. **Never skippable** — regardless of how the tally beat was skipped or fast-forwarded, the finale always plays in full; it's the one moment this deferred-scoring mode is never allowed to truncate.
4. The settled final score gets a slow, shallow idle pulse so the result screen doesn't go completely static while the player reads it. If this attempt beat the stage's stored best score, a **separate "NEW BEST!" flourish** fires alongside — its own sound (not the finale stinger) and a glowing badge positioned directly above the score (rather than floating beside it), which also permanently brightens the score's own outline for the rest of the screen — deliberately kept out of the finale's hit-stop/punch/wash package so it reads as its own secondary "oh, and also" beat rather than being folded into the slam. Below the score, one supporting line reports whichever fact is actually new information — the previous record on a fresh best, or the standing record otherwise — rather than repeating the score that's already the biggest thing on screen.
5. If this attempt cleared the stage with **every timer graded PERFECT**, a second, distinct **"ALL PERFECT!" celebration** fires (staggered ~0.55s after NEW BEST if both land on the same clear — they're independent and can co-occur) — its own sound, and a deep bronze-gold colour deliberately *darker/richer* than the New Best badge's plain gold, not a paler or brighter variant of it, so the two read as two different kinds of news at a glance. This flag is binary and permanent per stage (no tier/rank system) — once earned it never needs re-earning on a later, worse clear. If the attempt *wasn't* all-PERFECT but came close (3 or fewer non-PERFECT stops), a quieter **near-miss line** appears in the same reserved lane instead ("2 GOODS AWAY FROM ALL PERFECT") — naming the specific grade when the attempt missed on only one kind, or a plain stop count if it was a mix. Nothing shows here on a rougher clear, to avoid a discouraging tally of everything that went wrong.
6. **Colour language**: cyan (the same accent every interactive button already uses) is the standard-success colour throughout this screen — the "STAGE CLEAR!" headline, the finale's mid-tier wash — with gold reserved specifically for the New Best record and the deeper bronze-gold reserved for All-PERFECT. Green does not appear anywhere on this screen (it survives only as the separate, game-wide GOOD grade colour on the transient per-stop signs).
7. Buttons: **NEXT STAGE** (primary, filled) and **RETRY** (secondary, same cyan family at a lighter weight) — or a campaign-complete message + a de-emphasized **BACK TO TITLE** text link on the last stage. Both RETRY and RETRY-from-Endless-end-screen and PauseMenu's RESTART share a common fade-to-black-and-back screen transition before restarting, so retrying always reads as one consistent beat regardless of entry point. **Leaving** the result screen via NEXT STAGE or BACK TO TITLE (including the campaign-complete screen) instead plays a **tier-matched outro wipe** — brighter and faster for a strong clear, plainer and slower for a scrape-by one — reusing the same stage-quality tier from step 3 rather than a second metric. RETRY's transition is untouched by this and stays identical regardless of how the stage went.

A FAIL skips the tally/finale entirely and shows a plain FAILED summary with only a RETRY option (no skip, and no outro wipe on its RETRY).

### All-PERFECT tracking

Per Arcade stage, whether it has ever been cleared with every timer graded PERFECT in one attempt — a binary, permanently-persisting flag (`allperfect_stage_N`), computed from the same per-timer grade record scoring already keeps, with no separate tracking mechanism and no tier/rank system layered on top. Feeds two places:
- The stage-clear reveal's ALL PERFECT celebration / near-miss line, above.
- **Level Select** shows a small badge on every stage that has earned it: a bronze-gold ring with a tick, matching the result screen's own colour. Every other *unlocked* stage shows a hollow grey outline of the same shape instead of nothing — a visible "goal, not yet earned" slot rather than a badge that only ever appears once you already have it. Locked stages show neither. The moment a stage newly earns the flag, its badge shows hollow on the very next Level Select visit and then animates filling in (ring brightening, tick fading in, a small particle burst and stinger) a beat after the screen settles — staggered across stages if several were cleared before the player checked back, so a multi-stage haul reads as a rolling sequence of good news rather than one flash.

## 7. Endless mode

- **Progression-gated in two independent stages.** The title screen's ENDLESS button is locked until Stage 3 is cleared (tapping it while locked shows a short fading toast, no modal); clearing Stage 3 fires a one-time celebratory unlock notice — a closable popup (its own "NICE!" dismiss button), not an auto-fading banner, shown after that stage's own clear reveal rather than overlapping it. Once past that gate, the Mode Select screen is reachable and **Normal is immediately playable** — **Hardcore** stays independently locked *within that screen* until the full 12-stage campaign is cleared (its own toast on tap, and its own closable unlock popup on the campaign-complete screen). Hardcore's gate is deliberately later and separate from Endless's own gate, not the same flag.
- Chosen from a **mode-select screen** offering **Normal** (3 lives) or **Hardcore** (1 life).
- **3×3 grid** (9 cells). Timers spawn continuously into empty cells; the type, start value, and pacing all escalate with elapsed run time.
- **Spawn scheduler**: a new timer spawns when either (a) an already-running timer crosses below a low-time threshold (2.0s) for the first time, or (b) a fallback interval (2.0s, tuned in the scene) passes with no spawn at all — whichever comes first. This keeps the board from ever going empty or over-stuffed.
- **Simultaneous-timer soft cap** ramps from 2 timers at run start up to the full 9-cell grid by 90 seconds elapsed.
- **Start-value range** (how much time a fresh Normal-family timer counts down from) shrinks from a 5–7s window at the start down to a 1–3s floor by 60 seconds elapsed — timers get less generous as the run goes on. Blackout is deliberately exempt from this shrink, holding a fixed 7–8s range throughout, since its whole point is training the player to react to it by ear rather than a shrinking visible number.
- **Collision avoidance**: a new timer's spawn value is resampled (up to 20 tries) to keep its natural zero-moment at least 1.5s clear of any other currently-running timer's zero-moment, so two timers are never forced to hit zero in the same instant.
- **Type unlock schedule** (colored types become eligible to spawn over time, then compete by weight against whatever else is already unlocked):
  - Normal: available from the start, weight 72
  - Red: unlocks at 10s, weight 10
  - Blue: unlocks at 15s, weight 10
  - Golden: unlocks at 20s, weight 5
  - Blackout: unlocks at 30s, weight 3
  - Decay: unlocks at 40s, weight 6
- **Pity timer**: if 10 seconds pass with no colored (non-Normal) type spawning, the next spawn is forced to be a colored type.
- **Per-type concurrent caps** on the board at once: Red ≤2, Blue ≤1, Golden effectively uncapped (≤9), Blackout ≤1, Decay ≤2.
- **Lives**: a FAIL costs one life (banking the current segment's tally × multiplier into the run total first) and shows an X in the lives row; hitting 0 lives ends the run. Hardcore's single life shows no lives row at all (nothing to ever see filled). Losing a life gets its own distinct beat, sequenced *after* the FAIL's own shake/flash so the two read as "I failed" and then, separately, "and that cost me a life": the specific life icon just spent flashes bright and punches outward before settling into its spent-red state, paired with a life-loss sound reserved for this event alone (not reused from any FAIL audio).
- **Low-life ambient warning**: once remaining lives drop to or below a threshold (default: last life), a slow-pulsing deep-red vignette creeps in at the screen edges for as long as that state holds — the danger counterpart to the streak-heat glow below, built the same way but distinguished by both colour and behaviour (heat is a steady warm bloom; this never sits still). Deliberately calm rather than alarming: a slow breathing pulse, not a flash. Clears immediately on the run ending. **Suppressed entirely in Hardcore** — a one-life mode is always at the threshold, so an always-on danger signal would just be wallpaper rather than information.
- **Streak popups**: "Nx PERFECT!" appears at 2+ consecutive PERFECTs. A persistent **live streak counter** (top-right, visible only at 2+) sits alongside this, separate from the popup so a fast-changing streak doesn't fight one label's own text/tween state.
- **Pre-run target**: Mode Select shows a muted caption under each mode button — the player's current best score for that mode ("BEAT YOUR BEST: 17,240"), or "NO RECORD YET" rather than a bare zero when none exists — refreshed live so a record set since the last visit is reflected immediately.
- **Live overtake pulse**: the instant a run's live projected total first exceeds the loaded target for that mode, a one-time scale-pop + brief warm-white flash fires on both the TOTAL label and the live tally/multiplier equation — checked on every click against the live projected total (not only when a segment banks), so it fires the moment it's actually crossed rather than only at the next FAIL.
- **Milestone stingers**: fixed thresholds at 1000 / 5000 / 10000, then generated indefinitely past that by repeating ×2.5/×2/×2 multipliers (exactly ×10 every three steps, so every value stays round — 10,000 → 25,000 → 50,000 → 100,000 → 250,000 → ...) — resolves the open question this used to carry: thresholds scale rather than stopping dead at 10,000. Each still fires at most once per run (a fired-thresholds set, not a plain `>=` check, so a dip from a MISS can't retrigger one already passed). If a single stop crosses more than one threshold at once (an Overclocked Nuke on a full board, say), every one is marked fired but only the highest shows — it's strictly better information than the one it subsumes, and the two used to visibly collide on the same label. Renders in its own label so it can't collide with a streak-growth popup landing the same frame. The ×2.5/×2/×2 progression is a placeholder tuned by feel, not by measured data — retune it once real Hardcore scores exist to calibrate against.
- **Ambient ducking**: a synthesized drone bed's intensity tracks elapsed-time escalation directly (not a separate timeline), so the audio thickens in step with actual difficulty.
- **Mobile HUD layout** (Android, portrait): the pause/help icons sit top-right with margin for the phone's physical corner curve; the tally/multiplier equation and TOTAL sit centered below that icon row (not beside/behind it), at a bumped type scale. The combo meter bar that used to sit under TOTAL was removed outright — it stopped serving a distinct purpose once the live streak counter and the pre-run-target/overtake/milestone reactions above already answered "how's this run going." The 3×3 grid is centered on the real screen center (tracking the dynamic canvas height above, not a fixed offset that assumed the old fixed-height canvas), with the three powerup buttons repositioned to sit just above the fail-cross row at the bottom rather than directly below the grid — both the crosses and the powerup buttons were also sized up.
- **First-seen-type callouts**: the same first-seen-type flag Arcade's tutorial popups use also drives a lightweight, non-blocking callout the first time a type spawns in Endless with no flag set yet (regardless of whether it was first seen here or in Arcade) — a small label anchored to that timer for a few seconds, then it dismisses itself. Deliberately non-freezing: unlike Arcade's modal (which gates a stage that hasn't started) or the in-game Help bubble (an explicit request to pause and read), this fires on a board that's already live, so the clock keeps running through it.
- **End of run**: losing the final life plays its life-loss beat exactly like any other, then a distinct **stillness beat** (screen dims, ambient drops, board holds frozen) marks the transition into the summary rather than cutting straight from live play to a UI screen. The **summary reveal** counts up final score, best streak reached, and survival time in sequence — each landing with a punch, reusing the same digit-countup/pop technique as the Arcade reveal — with the whole reveal's intensity (punch size, burst presence, sound) scaled to how the run compares against the stored record it was chasing. The two supporting stats (best streak, survived) and the one record-comparison line beneath the score are presented as an aligned label/value table rather than freeform sentences, so all three lines' values line up on a shared column. Score, best streak, and survival time are each tracked as separate persisted bests per sub-mode; beating any of them fires one **combined** "NEW BEST" flourish naming whichever stat(s) improved (never one flourish per stat) — on a record, the flourish is layered with a full-screen colour wash, a brief freeze-frame, a second staggered particle burst on the score itself, and a slow idle shimmer on the score for as long as the summary stays on screen. RETRY available, sharing the same fade-to-black transition as PauseMenu's RESTART.

### Endless powerups

Three activatable abilities, Endless-exclusive, arranged in a column of buttons to the left of the grid. All three:
- Start every run already on a shared, flat 5-second cooldown (so they read as a mid-run relief valve, not an opening move).
- Have **no mutual exclusion** — any combination can be active at once.
- Are bound to keyboard shortcuts **A / S / D** in addition to clicking — the on-screen `[key]` hints are shown only on desktop/web; touch-only (mobile) builds omit them entirely rather than displaying a hint for a keyboard that doesn't exist.
- Have a distinct activation sound, a brief anticipatory "wind-up" visual at the button before the effect fires (the underlying mechanic itself is not delayed by this), and a small pulse/flash the instant they come off cooldown.

| Powerup | Cooldown | Effect |
|---|---|---|
| **Shield** | 20s | Arms a 10-second window. The very next FAIL anywhere on the board inside that window (from a mistimed click *or* an unclicked expiry) is silently downgraded to a MISS instead — no life lost. The window closes the instant it catches one, or when it times out unused. Visually: a calm cool-toned board-edge glow while armed; catching a FAIL triggers a distinct interrupt sequence (the FAIL's harsh feedback visibly begins, then is cut off and absorbed at the board edge) plus a unique "block" sound, clearly different depending on whether it actually caught something versus just expiring quietly. |
| **Nuke** ("Clear All" internally) | 30s | Instantly resolves every currently-live timer on the board as a PERFECT, staggered into a fast visual cascade (~0.34s total, ordered outward from the button) rather than all at once — each resolution gets its own particle burst and a note of a rising musical run, landing on a resolving chord at the end alongside a full-screen gold flash. Camera punch scales with how many timers were actually cleared. |
| **Overclock** | 25s | For 10 seconds, every timer on the board runs 1.5× faster **and** scores 2× as many points (the multiplier folds into the same bonus-factor pipeline as Red stacks/type bonuses). Visually: a persistent warm red screen-edge treatment for the whole window (distinct in both color and shape from the ambient "streak heat" glow, so the two never get confused even when both are active), plus a depletion bar on its own button showing the window closing (visually distinct from the normal cooldown ring). A clear (non-alarming) audio/visual cue marks the window ending. |

If both Overclock and Shield are active simultaneously, their two screen-edge treatments blend into a distinct combined visual state rather than just layering independently.

A **one-time tutorial popup** demonstrating all three powerups appears the first time the player actually commits to a run — right after pressing NORMAL or HARDCORE on the Mode Select screen, not merely on opening that screen — so a player who backs out without choosing either never sees it, and the run itself starts only once the popup is dismissed. Like the timer-type popups above, it shows a live three-timer demo strip playing the same scripted Shield/Nuke/Overclock animations the Help screen's powerups page uses (Shield's real FAIL→MISS save, Nuke's staggered cascade, Overclock's speed-up-then-revert), cycling through all three automatically and looping the whole cycle rather than stopping after one pass. GOT IT unlocks after the first full cycle finishes and stays unlocked while it keeps cycling.

## 8. Screens and navigation

All screens are procedurally-built `Control` trees inside one single scene (`Main.tscn`); a router shows/hides them by game state with a short cross-fade.

- **Title screen**: game logo (animated with a gentle per-letter sine-wave bob, synced loosely to the ambient menu music playing underneath), restructured into two tiers rather than one flat list: a **primary row** (ARCADE, ENDLESS — the actual gameplay decision, ENDLESS shown locked/greyed per §7 until unlocked), a **secondary row** of four square icon buttons (Options, Help, Scores, Credits), and a de-emphasized **Quit** text link (desktop-only — hidden on mobile, where the OS back-gesture/app-switcher already covers it; on Android specifically, back at the title screen instead prompts a confirm-to-exit dialog rather than quitting silently). A low-emphasis build-number label sits in the bottom-right corner, editable per-build via an Inspector-exported field rather than hardcoded. The four secondary-row icons are hand-authored SVGs (gear/question-mark/trophy/info, all gold-accented) rather than drawn primitives or text glyphs — see §2's icon note.
- **Level Select**: grid of 12 square stage buttons (bare stage number, e.g. "1".."12"), locked/unlocked as described in §6, each carrying the All-PERFECT badge described in §6's tracking subsection.
- **Endless Mode Select**: Normal / Hardcore choice (Hardcore locked per §7), plus the powerup tutorial on first visit. Each mode button shows its name left-aligned and its life count right-aligned within the button, rather than a single centered "NORMAL - 3 lives" string.
- **Help**: rebuilt from a static paginated legend into three swipeable pages of live, tappable demos, with tab headings at the top (the active page highlighted) and a row of page dots beneath the content advertising that the pages swipe (the active dot carries the screen's cyan accent and stretches into a short pill, the inactive ones stay muted grey). The Scores screen's hero-card dots mirror that same pill behaviour and go one step further, tinting each dot to its own page's mode — cyan for Normal, red for Hardcore — because those two pages genuinely *are* modes with an established colour already. Help's three pages have no equivalent: "Timers" spans six accents, "Powerups" spans cyan/gold/red, "Scoring" spans the five grade colours, so per-page tinting here would invent three new colour meanings rather than echo existing ones. Cyan-only on Help is therefore deliberate, not an omission. **Always reopens on page 1 (Timers)** regardless of which page the player last left on, since the screen stays in the tree hidden rather than rebuilt between visits. Every tile is a `HelpDemoTile` — a cosmetic-only replica of a real timer (never wired to EventBus/ScoreManager/AudioManager's gameplay path, so looking at the legend can't affect the game) — that sits idle showing only its name until tapped, then starts a **practice run the player times themselves**: a real countdown at 1x speed, the same tick and grade-resolution sounds the real board uses (background music ducks for the duration and restores after), a grade-accurate flash/pop/floating grade sign/click-burst, and the real per-type or per-stack score bonus (Golden ×2, Blackout ×2.5, a Red-boosted stop ×1.25) — while a full-canvas dim drops over everything else — the tile being practised and its caption are lifted above it, and it holds for as long as the caption does (through the resolution and every replay) rather than lifting the moment a run ends. The per-tile fade stays on top of that, separating the other tiles from the focused one inside the lit area. The tile is graded against `TimerSlot`'s own PERFECT/GOOD/OKAY/MISS windows, off the value at the instant the finger went **down** (a tap resolves on release so a swipe starting on a tile stays a swipe, but grading on release would score every stop later than the same tap in a real run — by more than the 0.05s PERFECT window is wide). Timers count from **4.00** down through zero to −1.00; running the clock out grades FAIL exactly as it does on the board. A small pulsing "TAP" under the digit marks a tile as currently stoppable. Once resolved — or missed — the run **replays from the top after a short delay**, separately tunable for "you stopped it" and "you never got to it", making the page an endlessly repeatable place to practise timing a PERFECT. Only the tapped tile ever runs; tapping a different one abandons the first. Tapping *anywhere* on the screen while a demo is playing — a different tile, or empty space — immediately cancels it (and closes the explanation panel below) rather than only a same-tile re-tap doing so. **Page 1** splits the six timer types into "affects only itself" (Normal, Golden, Blackout, Decay) and "affects the whole board" (Red, Blue — the only two whose rule reaches other timers); the latter group's two "bystander" Normal timers (themselves tappable and player-timed, starting at 6.00 and 8.00 so they are still running when the reaction lands) fade in/out only while Red or Blue is actually being practised, and the reaction fires on **any** resolved grade rather than only a clean stop, matching the board's own rule, inside a row that permanently reserves its space so the rest of the grid never visibly shifts as they appear. Tapping a type opens a panel anchored directly beside that tile (flipping above it when below would run off the page or cover the bystander row) rather than a fixed block of text elsewhere on the page, closing the distance between "what you tapped" and "what it does." Golden never counts and never expires — it churns until taken, so it has no expiry beat and only turns over on a tap; Decay instead climbs 0.00 → 4.00 with its tier boundaries held at the real windows' proportions. **Page 2** is a live practice board rather than a preview strip: a permanently-running 2×2 of Normal timers (4/5/6/7s, restarting as a group once all four resolve, so a powerup always lands on a full board), an explanation panel, and genuine `PowerupBar` buttons at the real board's own size below it. The buttons fire real `Powerups.activate()` calls under a practice mode that keeps effect *durations* real while suppressing *cooldowns* — so Overclock and Shield need no special-casing at all (the tiles read `timer_speed_scale()` and route FAILs through `filter_grade()` exactly as a board slot does), and only Nuke, which has no per-timer state to read, runs its own cascade mirroring the real one. Practice mode and an armed run are mutually exclusive by construction, so this can never reach into live charges. (The in-game Help bubble's powerups page keeps the older scripted three-timer preview — it opens mid-run, where a live practice board would have nothing safe to act on.) **Page 3** is two live instruments rather than a demo to watch. A **signed distance slider** centred on 0.00 — negative to the left (already past zero), positive to the right (still approaching), the same sign convention `current_time` uses on the board — sits under a zone bar of the PERFECT/GOOD/OKAY/MISS/FAIL bands mirrored either side of centre, with a slice of FAIL shown past the MISS boundary at both ends so the losing zone has a visible edge rather than an implied one. Dragging it reads out the signed value, the grade and the points live. Below that, a **multiplier chain**: tapping any of the five grades appends a colour-coded grade-name chip to a ledger and evolves a running multiplier by the real rule, with a RESET returning it to the floor — deliberately showing the multiplier alone, with no tally or accumulated points, since the slider above already covers points-per-stop. Neither half re-implements anything: the grade comes from `TimerSlot.grade_for_distance()`, the points from `ScoreManager.base_points()`, and every chain step from `ScoreManager.next_multiplier()` / `reset_multiplier()` — the same functions the board runs on, called read-only, so the page never touches real score state. The slider's range and the zone bar's band widths are both computed from the live grade thresholds at build time rather than written down, so retuning a threshold (see §4) reshapes this page automatically. The page scrolls vertically when its content exceeds the viewport, which on a typical tall phone it does not.
- **In-game Help bubble**: a "?" icon, top-right during live play in both modes (clear of the pause button), opening a compact reference panel without leaving the stage — one page (timer types) in Arcade, two (timer types, then powerups) in Endless, paginated with the same nav component the Help screen uses, its heading swapping between "TIMERS" and "POWERUPS" to match whichever page is showing. Opening freezes every gameplay clock (timers, Endless's spawn scheduler and unlock schedule, powerup cooldowns) the same way Nuke's cascade does, closing via the same wipe transition the Pause Menu's RESUME uses. The bubble's dim also blocks mouse/touch from reaching the board underneath, but opening it additionally suspends powerup **input** as its own explicit state, separate from the clock freeze — Shield/Nuke/Overclock's keyboard shortcuts (A/S/D, desktop/web only) stay live otherwise, since the tree itself is never paused here. System back (Android) or Escape closes the bubble rather than opening the Pause Menu, even though the Pause Menu's own handler would otherwise see the press first. Shows a subtle pulsing badge whenever a spawn-eligible timer type hasn't been seen yet (meaningful mainly in Endless, since Arcade's tutorial popups already flag every type before this icon is ever visible) — opening the bubble itself marks every currently-eligible type as seen, since its own page 1 is exactly the information the badge was flagging, rather than waiting on that type to separately spawn and trigger Endless's live callout.
- **Scores**: summary before detail, then a scrollable stage list. At the top, a swipeable hero card shows Endless's best score — one page each for Normal and Hardcore, colour-coded to Mode Select's own cyan/red so the two already read as the same modes before the label does, with a page-dot pair beneath it (opens on whichever mode actually has the higher score). Below that, a plain summary line ("N OF 12 STAGES PERFECTED"). The stage list itself is a scrollable, edge-to-edge column of individually-panelled rows (one per stage, matching the dark-tinted-plate-plus-border language every other timer/tile/card in the UI already uses) rather than a bare hairline-separated table — each row shows the bare stage number, the same bronze-gold All-PERFECT ring-and-tick mark Level Select uses (reused, not redrawn, so both screens can never show a different verdict for the same stage), and the best score; the optional hand-authored target is no longer shown as its own column, since the mark already answers "was this stage fully cleared" without a second number restating it. A stage that just earned its mark plays the same hollow-to-filled reveal animation Level Select plays — reusing that exact system rather than a second one, so whichever screen the player checks first after earning a stage is the one that gets to show the reveal.
- **Options**: three (four in a debug build) separate cards, stacked, rather than one shared panel with labelled sections inside it — the visual hierarchy now matches each setting's actual risk. AUDIO and DISPLAY share the original neutral card: SFX and Music full-width sliders, each leading with a hand-authored icon (`icons/options_speaker.svg`/`options_note.svg`, house SVG style, cyan); "Reduce screen effects" is a pill toggle with its own eye icon and a one-line explanation beneath its label, the whole row tappable as a single 48dp target. Both sliders give audible feedback while dragging rather than only applying silently: SFX plays a short debounced tick through the bus whose volume the drag is actively changing; Music previews/ducks the real menu track at the dragged level even when it isn't otherwise playing (the Pause Menu's Options overlay, where gameplay deliberately keeps this bus silent) — a preview `AudioManager` owns independently of the panel, so it can never leave real music running behind once the player resumes. Under the toggle, a small always-looping two-swatch preview shows a NORMAL flash beside a REDUCED one that never fires — reusing the real FAIL flash's own colour and duration (`Juice.ABERRATION_COLOR`/`ABERRATION_MS`) rather than a softened fake, since the toggle is a hard on/off in the real code, not a fader. DATA is its own separate card: a visible red wash and border (the same `#ff2e5e` used for Hardcore/FAIL everywhere else, not a new colour) so **RESET PROGRESS** reads as dangerous before it's even tapped, with its own trash icon. Its confirmation step carries the same red styling into its own bordered panel rather than falling back to a plain dialog, states plainly what's cleared (progress only — audio/display preferences survive, per the same reasoning "Reduce screen effects" itself exists for), and puts CANCEL first at full weight with ERASE second and visually secondary (outline-only, narrower — but never shorter: both clear the same touch-target height) so an accidental double-tap can't land on the destructive option. DEBUG (the dev grade-forcing control) is its own quarantined card, dashed-bordered, labelled "DEBUG - NOT SHIPPED" in a letter-spaced technical face, its icon deliberately flat with no glow backing unlike the other four — and it is not merely hidden in a release build, it is never added to the scene tree at all (`OS.is_debug_build()` gates the whole card's construction, the same proven pattern the control itself already used before this pass), with no reserved gap left behind either. The whole screen sits on a `ScrollContainer` now rather than a fixed `CenterContainer` — measured, the full stack overflows a 9:16 portrait canvas by 320 units and a 1600×900 landscape one by a comparable margin, so both orientations scroll (a no-op when content already fits).
- **Credits**: one flowing composition rather than a flat labeled list, built around a single emotional focal point instead of several equally-weighted facts. A hero credit block ("Designed & Developed by MAKSTER", a small heart icon, and one merged thank-you/jam-origin statement) is followed by a divider, then a quiet "colophon" row of two peers (the licensed music track's attribution, the engine credit) each with one highlighted line and plain supporting detail, then a second divider, then a feedback block ending in a real **EMAIL US** button (opening a pre-filled mail draft) rather than an in-page hyperlink. Reachable from the title screen's secondary row.
- **Pause menu** (in-game, both modes): on Android (portrait), all four buttons — **RESUME**, **RESTART**, **OPTIONS** (as an overlay), **BACK TO TITLE** — now share one uniform footprint and glow treatment, stacked in a single column, rather than RESUME being uniquely large/glowing with OPTIONS/BACK TO TITLE demoted into a small paired row (the original three-tier hierarchy, which desktop/web still uses unchanged). Accent colour is still what distinguishes them (RESUME/RESTART/OPTIONS cyan, BACK TO TITLE grey). RESUME dissolves the whole pause overlay via a shared ~0.5s wipe rather than a numeric countdown — the same transition the in-game Help bubble's close uses, so both read as one consistent "overlay lifts, board becomes interactive again" beat; the pause icon itself fades back in across that same beat rather than reappearing only once the wipe finishes.

Every heading title across Options/Endless-select/Help/Scores uses the same animated per-letter wave text as the title screen, for visual consistency. Every plain **BACK** button (Scores, Help, Credits, Level Select, Endless Mode Select, Options) is likewise unified: 200×64 in landscape/desktop — with Credits and Level Select deliberately at 220×64, one size class up, since both sit under noticeably larger content (Credits' scaled composition, Level Select's big stage squares) and 200 read undersized against it — bumped per-screen in Android portrait to clear 48dp, the same cyan as the title screen's ARCADE button, and centered as the last item of that screen's own content column rather than pinned to a corner. ("BACK TO TITLE" buttons that sit in a row alongside RETRY/RESTART/NEXT STAGE — Pause Menu, Stage Result, Endless End — are a separate case; on Android portrait these rows now share one unified 380×140 lit-glow button treatment across all three screens, with text sizes bumped well past the original — see §10.)

## 9. Accessibility / settings

- **SFX volume** and **Music volume** are independent, each persisted, each driving its own audio bus.
- **Reduce screen effects** toggle: hard-disables (not merely softens) screen shake, camera punch/pull, hit-stop, and every full-screen flash or color wash — these are treated as motion-sickness triggers that can't be "softened" into comfort. Explicitly does *not* touch: localized particle bursts, click-point effects, label pops, or persistent state-indicator glows (Overclock/Shield edge treatments, the streak-heat glow, and the Endless low-life vignette all stay at reduced-but-nonzero visibility, since the player still needs to know those states are active). The Arcade reveal's pre-tally anticipation tint sits between the two conventions and is scaled down (not removed) — a persistent background tint like the state-indicator glows above, but full-screen like the washes/flashes the toggle otherwise kills outright.
- Save data (all high scores, unlock progress, settings, first-seen-type/tutorial flags, Endless best score/streak/survival-time per sub-mode) lives in a single generic key/value store, degrading gracefully (warning + "not saved," not a crash) if the save file can't be opened. **RESET PROGRESS** (Options → DATA) is layered on top of this: the underlying store has no notion of "progress" vs. "preferences" and wipes everything on a reset, so the player's current audio/display settings are re-written back to the fresh file immediately afterward rather than being left to silently revert to defaults on next launch.

## 10. Android platform support

**Android is portrait-only**, hard-locked at the manifest level (`android:screenOrientation="userPortrait"` — confirmed by dumping an actual exported APK's manifest, not just trusting the export setting) — there is no in-game orientation toggle and no player choice; a `Layout` autoload governs the canvas that every screen is built against. Portrait canvas **width is fixed at 900** (every dp/touch-target number and the gameplay board's own sizing is calibrated against it), but **height is computed dynamically from the real device's aspect ratio** at runtime (recomputed on rotation/split-screen/fold), rather than a fixed 1600 — this replaced the original fixed-height canvas after it was found to leave real, unfilled letterbox margins (painted over with a matching backdrop, but not eliminated) on any device whose aspect wasn't exactly 9:16, which is nearly every Android phone. A portrait-specific type/spacing scale factor (`PORTRAIT_SCALE`/`_s()`, tuned per-screen against that screen's own measured content) layers on top of the fixed width so text and controls read at a comfortable size on a phone rather than at desktop scale shrunk to fit. **Desktop and web remain landscape-only** (1600×900 fixed), completely unaffected by any of this — the orientation setting only touches handheld exports.

- **App lifecycle**: losing focus (backgrounding, an incoming call, split-screen, alt-tab on desktop) auto-triggers the same pause-freeze the Pause Menu button uses. It deliberately does not auto-resume on refocus — the player has to explicitly press RESUME, so a run can't silently keep ticking while the screen was elsewhere.
- **System back button**: mapped per-context rather than left to Android's default (which would otherwise quit the app instantly from any screen). In-game, back opens the Pause Menu; in any menu, it triggers that screen's own existing BACK handler; at the title screen, it prompts a confirm-to-exit dialog. Implemented as a single bridge (Android's back gesture is republished as the same `ui_cancel` action every screen's Escape-key handler already listens for), not a second parallel input system.
- **Viewport centering (pillarboxing)**: the game's UI is built entirely with fixed-canvas pixel positions, not anchors, against whichever canvas size the current platform/orientation resolves to. On a real device whose aspect ratio doesn't exactly match that canvas, the shared scene root (`Main`, a `Node2D` every screen is a child of) is centered within the actual device viewport — not a per-screen fix. A full-bleed background now sits behind everything at the `Main` level so the resulting letterbox bands read as part of the game rather than a stark engine-clear-colour cut, and every full-screen gameplay effect (Nuke flash, Shield/Overclock edge treatments, vignettes, screen transitions) reaches those same true edges rather than stopping at the logical canvas boundary.
- **Safe-area handling**: corner-pinned UI (the in-game Help icon, the Pause button, the title screen's version label and Quit link, Endless's bottom fail-crosses row, the Stage Result screen's whole reveal column) insets itself away from notches/gesture-nav-bars/rounded corners, queried via the display's actual safe-area rect and converted into the game's canvas coordinate space. The conversion correctly re-runs whenever the portrait canvas's own dynamic height changes (not just on a raw window resize), and translates the display's safe rect into the window's own coordinate space before intersecting the two — needed because the two are reported in different frames (screen space vs. window space), which only coincide on a fullscreen app; under split-screen, multi-window, or a free-form/DeX window they don't, and treating them as the same thing would misread the window's own on-screen position as part of the inset.
- **Dynamic portrait height is clamped** (roughly 1200–2400 canvas units) rather than trusting the device aspect ratio unconditionally — `userPortrait` locks ordinary rotation, but not split-screen, an unfolded foldable, or a free-form/DeX window, any of which can report an aspect ratio that would otherwise collapse the canvas below the height every portrait screen's absolute layout assumes.
- **Crash/error logging and save safety**: a lightweight local error log exists for conditions the game degrades from gracefully (corrupt save, failed write) but that previously vanished silently with no way to see them on a device with no attached console. Save reads are cached in memory rather than re-opening the file on every check (a real stutter/ANR risk that existed on the hot path of a per-frame UI check), and settings writes (e.g. a dragged volume slider) are debounced rather than writing to disk on every intermediate value.
- **Restart/retry hygiene**: starting a fresh Endless run or Arcade stage (including a pause-menu RESTART) explicitly clears any still-running powerup aura, particle burst, or in-flight sound effect left over from before the pause — pausing itself never changes the game's high-level state, so nothing about "leaving play" would otherwise fire for a same-state restart, and a leftover animation/sound could otherwise bleed into the new run. Extends to a Nuke cascade specifically: each run carries its own generation marker, so a cascade paused mid-flight and abandoned by a RESTART recognizes it no longer belongs to the run that resumes and neither fires its completion effects into it nor releases a gameplay freeze that belongs to whatever froze next.
- **Touch target sizing**: every screen now clears Android's ~48dp minimum recommended touch target on a small phone screen. The on-device-screenshot audit approach was carried across every screen in turn — Help's scoring-page grade chips/page tabs/BACK button (32.4–38.3dp, since raised past 48/56dp), plus a text-contrast issue on the same screen (Blackout's tile name, plain-fill against its own recessive panel colour at 3.19:1 against the 4.5:1 WCAG AA floor, fixed by outlining it the same way the digits already are); Options' sliders and its (since-replaced) checkbox (14.4dp, now spanning the screen's full width at 48dp); Scores' table text and BACK button (11.6dp / 30.7dp). The corner-pinned pause button and in-game "?" Help icon — flagged and deliberately deferred through all of the above passes — were finally brought up to size too (26–46dp → ~48dp), along with every plain BACK button, every screen's action buttons (Stage Result/Endless End/Pause Menu/Tutorial popups all unified on a shared 380×140 button treatment in portrait), and the Title screen's primary buttons/icon row. Same convention throughout: 1 canvas unit ≈ 0.4dp, so 120 raw-canvas-unit-equivalent ≈ 48dp and 140 ≈ 56dp. Each screen's own `PORTRAIT_SCALE` means the raw pre-scale constant differs per screen; what is guaranteed is that every screen clears the floor, **not** that the effective dp is identical across them. The plain BACK buttons, for instance, settle into two classes — ~49dp on Credits/Level Select/Endless Mode Select and ~57.6dp on Help/Options/Scores — both comfortably above the 48dp minimum but not the same number.
- **Export/build status**: an Android export preset exists (package `com.makster.perfectzero`, `armeabi-v7a` + `arm64-v8a`), debug deploys work end-to-end via Godot's Remote Deploy (build + install + launch + live debugger, tested on a real device over USB). Launcher icons (a flat legacy icon plus adaptive foreground/background/monochrome layers) are hand-authored SVGs following the same no-`<text>`/no-glow-filter rules as the title screen's icons. **Not yet done**: Min/Target SDK haven't been deliberately checked against Google Play's current policy (still on Godot's defaults), no release keystore exists yet, and no signed release AAB has been built — all of this is release-side work, separate from the debug/testing loop, which is fully working.

## 11. Known accepted design limits

- Stages 3 and 6 (all-Golden) cannot be failed by design.
- An unclicked Golden timer in Arcade can stall a stage indefinitely — no forced auto-resolve exists; this is an accepted risk rather than a bug.
- Endless's Nuke can be activated mid-cascade-of-another-Nuke or during other transient animations; the game freezes all gameplay clocks (timer countdowns, powerup cooldowns/windows) for the duration of any such scripted animation, so none of this can desync scoring — nothing "runs" behind a frozen screen.

## 12. Planned, not yet implemented

Nothing currently outstanding from the Reward & Feedback Systems brief — all of §4-7's points are implemented (see §7). Two smaller items remain open:

- A colourblind-friendly encoding for timer identity — the actual game board (unlike the Help screen's legend, which also names each type) encodes Red/Blue/Golden/Decay almost entirely by hue. Flagged as a real accessibility gap, not scheduled.
- A dedicated full-campaign-complete screen (currently a stub print + reused result-screen message).
- A Shield-absorbed expiry currently plays the same full harsh expire tone as an ordinary FAIL, even though the visual reaction correctly stands down and defers to the block/absorb sequence instead. Whether the audio should stand down too (matching the visual) or is meant to stay as a "that nearly hurt" audible tell is an open feel question, not yet decided.
